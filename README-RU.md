# Onto4

**Onto4** — контекстно-зависимая четырёхзначная система семантических
вердиктов. Она отделяет корректность формализации от истинности и не
предоставляет сама по себе ни полномочий, ни разрешения на действие.

Исторический репозиторий проекта: [LimiNode/Onto4](https://github.com/LimiNode/Onto4).

## Четыре значения

| Значение | Смысл |
| --- | --- |
| `T` | формализация корректна и утверждение истинно в выбранном контексте |
| `F` | формализация корректна и утверждение ложно в выбранном контексте |
| `U` | формализация осмысленна, но `T`/`F` пока не установлено |
| `C` | category error: формализация не допускается выбранной онтологией или семантикой |

`C` — это результат проверяемой ошибки типов, ссылок или пресуппозиций. Оно
не означает «нет данных», не является синонимом `U` и не следует автоматически
из отсутствия объекта в текущем состоянии модели. Например, утверждение о
несуществующем единороге может быть обычным `F`, если термин и предметная
область заданы корректно. Настоящий пример `C`:

```text
Mass : PhysicalObject -> MassValue
integer_7 : Integer
Mass(integer_7) > 1000 kg  -> C
```

## Контекстная оценка

Значение не является свойством одной строки. Оценка имеет вид:

```text
V(P | ontology, semantics, epistemics, inference, perspective)
```

`ContextFrame` фиксирует эти профили, их версии, допущения и доступную
перспективу. Одна и та же фраза может получить разные значения в разных
контекстах. Отсутствие достаточных свидетельств даёт `U`, а не `C`.

Например, структуру контекста можно выразить так:

```cpp
struct ContextFrame {
    OntologyProfile ontology;
    SemanticProfile semantics;
    EpistemicProfile epistemics;
    InferenceProfile inference;
    Perspective perspective;
};
```

Проверка смысла — это этап формализации и типизации перед логическими
операторами, а не обязательный оператор `Sense` внутри самой логики.

## Onto4 и Evidence4

Onto4 описывает семантический статус. Состояние свидетельств ведётся
отдельно в пространстве `Evidence4`:

```text
Neither | TrueOnly | FalseOnly | Both
```

Например, `Onto4 = U` и `Evidence4 = Neither` означает осмысленное
утверждение без принятой поддержки, а `Onto4 = U` и `Evidence4 = Both` —
осмысленное утверждение с конфликтующими свидетельствами. `Both` не является
`C`.

## Каноническая strict-семантика и determining-проекция

Канонический профиль Onto4 — **strict**: составное высказывание оценивается
целиком, поэтому category error в обязательном операнде не скрывается:

```text
¬C = C
C ∧ X = C
C ∨ X = C
C -> X = C
X -> C = C
```

Это выбрано намеренно: недопустимая онтология или скрытая пресуппозиция не
исчезает за истинной/ложной веткой, а результат остаётся композиционным,
аудируемым и воспроизводимым. Strict отвечает на вопрос: «допустима ли вся
данная формализация и какой вердикт из неё следует?»

Например, пусть `A = T` означает корректное утверждение о существовании деда
в реконструируемом прошлом, а `B = C` — недопустимое в данной онтологии
абсолютное свойство `WasAbsolutely(дед)`. Тогда объектная формула `A ∨ B`
имеет значение `C`: возвращать `T` означало бы скрыть ошибочную ветвь.

Оптимизационная **determining/short-circuit-проекция** всё равно полезна:
`T ∨ X` или `F ∧ X` иногда уже определяют ответ запроса. Но это слой
разрешения запросов, поиска, decision policy и выбора кандидата, а не
каноническая семантика истины. Пропущенная ветвь, её контекст и диагностика
должны сохраняться; в доказательстве, аудите и replay она не может быть
заменена determining-результатом.

Если кандидаты формализации дают `F1 -> T` и `F2 -> C`, мета-уровень вправе
выбрать допустимый `F1` по правилу «существует хотя бы одна допустимая
формализация». Нельзя кодировать это как объектную формулу `F1 ∨ F2`.

Другой пример — идентичность во времени. Отношение
`Continuity(me_child, me_now)` может иметь значение `T`, тогда как более
сильный предикат `SamePersistentSubstance(me_child, me_now)` получает `C`, если
выбранная онтология вообще не содержит категории постоянной субстанции.
Strict сохраняет это различие; determining-запрос может выбрать корректную
реляционную формализацию, не утверждая недопустимую.

## Операторы

Таблицы в [docs/truth-tables-ru.md](docs/truth-tables-ru.md) имеют статус
**чернового профиля**. Для строгой оценки category error распространяется на
составную формулу до обычного вычисления `T/F/U`. Операционный short-circuit
допустим только при сохранении пропущенной ветви и её диагностики.

Если используется определение:

```text
A -> B = ¬A ∨ B
```

таблица импликации должна ему соответствовать. Эквивалентность по умолчанию
выводится как `(A -> B) ∧ (B -> A)`. Любой иной профиль обязан назвать себя
отдельно и опубликовать полные таблицы.

До принятия алгебры необходимо проверить заявленные свойства операторов:
ассоциативность, коммутативность, законы де Моргана, дистрибутивность и
связь с выбранным порядком информации.

## Примеры

```text
2 + 2 = 4                         -> T
Слон меньше муравья               -> F
Завтра пойдёт дождь               -> U
Mass(integer_7) > 1000 kg         -> C
```

Старый пример «Интернет существовал в 0 году» не должен автоматически
получать `C`: при заданной исторической интерпретации это `F` или `U`, а не
ошибка категории.
