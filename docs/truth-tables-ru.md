# Таблицы операторов Onto4 (черновой профиль)

Этот документ фиксирует **черновой**, а не окончательно принятый профиль
операторов. Сначала проверяется корректность формализации в закреплённом
контексте, затем вычисляются логические связки.

| Символ | Значение |
| --- | --- |
| `T` | корректно сформулировано и истинно |
| `F` | корректно сформулировано и ложно |
| `U` | осмысленно, но `T`/`F` не установлено |
| `C` | category error: некорректный тип, ссылка или пресуппозиция |

`C` не означает отсутствие свидетельств и не означает, что объект просто не
найден в текущей модели. Диагностика семантического checker-а должна показать,
почему выражение недопустимо.

## Разделение проверки и вычисления

В строгом профиле любой `C` в составной формуле сохраняется как `C`;
семантическая/type-проверка охватывает весь AST до вычисления truth-value.
Короткое замыкание (`F ∧ X = F`, `T ∨ X = T`) допустимо только как
операционная оптимизация: оно может пропустить вычисление truth-value `X`, но
не проверку типов и категорий. Если ветвь ещё не проверялась, результат должен
содержать `semantic_check_deferred`, а не притворяться, что ветвь корректна.

## Отрицание

```text
¬T = F    ¬F = T    ¬U = U    ¬C = C
```

## Конъюнкция и дизъюнкция

Для операндов без `C`:

| A | B | `A ∧ B` | `A ∨ B` |
|---|---|---|---|
| T | T | T | T |
| T | F | F | T |
| F | F | F | F |
| T | U | U | T |
| F | U | F | U |
| U | U | U | U |

Если `A = C` или `B = C`, строгий результат обеих связок — `C`.

## Импликация

В строгом профиле сначала проверяются категории:

```text
A -> B = C, если A = C или B = C
A -> B = ¬A ∨ B, иначе
```

| A | B | `A -> B` |
|---|---|---|
| T | T | T |
| T | F | F |
| F | T | T |
| F | F | T |
| T | U | U |
| U | T | T |
| U | U | U |

Если профиль хочет, например, `F -> C = T`, он должен объявить импликацию
отдельной примитивной связкой и привести полную таблицу, не смешивая её с
определением через `¬A ∨ B`.

## Эквивалентность

По умолчанию:

```text
A <-> B = (A -> B) ∧ (B -> A)
```

Примитивная эквивалентность допускается только при явном описании отличий и
отдельных тестах.

## Независимая ось Evidence4

Свидетельства не кодируются заменой `U` на `C`. Используется отдельное
пространство:

```text
Neither | TrueOnly | FalseOnly | Both
```

`Onto4 = U, Evidence4 = Neither` и `Onto4 = U, Evidence4 = Both` — разные
ситуации, но обе остаются семантически корректными.

До принятия профиля как теории нужно проверить ассоциативность,
коммутативность, законы де Моргана, дистрибутивность и совместимость с
выбранным порядком информации.

Для текущего strict-профиля обычная часть `T/F/U` сохраняет ожидаемые
коммутативность, ассоциативность, законы де Моргана и дистрибутивность. При
поднятии `C` как semantic failure закон поглощения уже не является общим:

```text
A ∧ (A ∨ C) = C, а не A
```

Это явное ограничение semantic-error lifting, а не повод молча помещать `C` в
truth/information lattice.
